## Measured output

### NHWC AVX2 versus PyTorch

Both versions double the image height and width, then join the skip input.
Both use NHWC storage and 32-bit floating-point numbers. Input and output buffers are ready before timing.

- Baseline: PyTorch nearest-neighbor upsampling, followed by concatenate.
- Our version: the same work combined in one AVX2 C function.
- A is YOLOv8n layers 10+11. B is layers 13+14.

Machine: ece020.ece.local.cmu.edu, Intel(R) Xeon(R) Silver 4208 CPU @ 2.10GHz, CPU 0, one thread. PyTorch 2.5.1+cpu.
Times are in milliseconds. Smaller is better. Speedup is PyTorch time divided by AVX2 time.

| Image | Stage | PyTorch ms | AVX2 ms | Speedup |
|---|---|---:|---:|---:|
| 640 | A | 0.3558 | 0.1825 | 1.95x |
| 640 | B | 0.7887 | 0.3730 | 2.11x |
| 1024 | A | 1.1259 | 0.5379 | 2.09x |
| 1024 | B | 2.8059 | 1.8872 | 1.49x |
| 2048 | A | 6.2022 | 3.7151 | 1.67x |
| 2048 | B | 12.8276 | 7.5889 | 1.69x |

A+B adds the two stage times above.

| Image | PyTorch A+B ms | AVX2 A+B ms | Speedup |
|---|---:|---:|---:|
| 640 | 1.1445 | 0.5554 | 2.06x |
| 1024 | 3.9318 | 2.4250 | 1.62x |
| 2048 | 19.0298 | 11.3040 | 1.68x |

Every output byte matched. Inputs and the bytes around the buffers stayed unchanged. Checks included NaNs, infinities, signed zero, random bits and buffers starting four bytes past an aligned address.

Each case was measured in three separate runs. Each run used 21 rounds, four warmup calls and five timed calls per round. The table uses the middle timing from each run, then the middle of those three values.

The PyTorch baseline also has its temporary upsample buffer ready before timing. AVX2 avoids that temporary buffer. No layout conversion is timed because both versions already use NHWC.

These numbers cover only upsampling and concatenation, not the full YOLOv8n model.
